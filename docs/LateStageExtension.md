# Hunnedalen 泥石流后阶段扩展

> 下文描述保留的旧程序动画模式。当前工程默认采用严格 LS-DYNA 数据模式，缺少真实结果时不会自动生成本页所述后阶段。切换原演示与接入新数据请见 [LS-DYNA 接入说明](LSDyna.md)。

基于原有 `Unity_Project` 的桌面和 VR 场景增加继发山体滑坡。原场景、地形高度、RAMMS 帧数据、前期水流材质、预警、天气、玩家控制及菜单继续使用原工程内容。

## 运行

用 Unity 打开工程，然后打开 `Assets/Breach/Scenes/DynamicScenes/Hunnedalen_DSK.unity`（桌面）或 `Hunnedalen_VR.unity`（VR），按 Play。新增组件在这两个场景运行时自动建立，不需要更换场景或重新挂接原交互脚本。

默认时间线：

| 场景时间 | 过程 |
|---|---|
| 0–238 秒 | 原预警、自由探索和 RAMMS 泥石流播放 |
| 242–254 秒 | 新增后阶段：张裂缝扩大、零星落石和低频声响 |
| 254–262 秒 | 边坡由下部向上部渐进失稳，大片岩土脱离 |
| 262–300 秒 | 大块岩土滑移、碎裂与滚动，碎屑涌浪沿原地形扩展 |
| 300–320 秒 | 坡脚碎屑扇与大块堆积保留，粉尘和沉积物雾逐渐消散 |

实际触发时刻读取原 `SimulationManager` 的结束时间；修改原预警、探索时间或播放速度后，扩展随原时间线调整。后阶段响应原播放／暂停状态，原帧号回退时清除新增效果。

## 快速预览

打开 Hunnedalen 场景后选择 **Landslide → Late stage → Preview on original terrain**。预览窗口可拖动后阶段时间或直接播放；关闭窗口或点击“恢复原场景”会删除临时预览。

默认继发失稳区为 150 × 180 米，厚度表现为 6 米，演化路线约 600 米。位置依据原 RAMMS 初始运动区域确定，路径沿原 Terrain 高度采样；这些尺寸是动画情景参数，不能作为现场反演结果。修改 `LandslideSettings` 的默认参数可调整范围和时长。

## 实现与数据边界

前期仍使用原 RAMMS 结果。新增后阶段使用 Unity 中可重复播放的地形贴合动画：分块失稳、角砾岩块滚动、连续碎屑涌浪、裂缝、沉积物雾和空间声响。新增效果不向原 `TerrainData` 写入高度，不重新定位原地形、道路、建筑或玩家。

后阶段是增加的继发灾害情景，不代表 Hunnedalen 2016 年事件被证实经历过同样的大型山体滑坡。当前后阶段轨迹没有经过新的 Ansys／LS-DYNA 求解，不应将动画中的速度、堆积厚度或视觉体量用于定量判断。

原工程下载包中的部分 DLL、贴图和模型是 Git LFS 占位文件。恢复的资源来自同一原仓库，按原占位文件给出的 SHA-256 和长度验证。恢复资源属于补齐原内容。

本机 Unity 为 2022.3.62f3c1；原工程为 2021.3.2f1。为了保持旧版天气渲染接口，工程使用 Unity 官方 `2021.3/staging` 分支的 URP / Core / ShaderGraph 12.1.16 源码作为本地依赖，并完成 Unity 2022 的 RendererList 接口更新；没有改写原天气效果或玩家交互脚本。工程版本信息已对应本机编辑器，避免自动升级到不兼容旧天气接口的 URP 14。

## 检查说明

桌面原场景的播放检查覆盖：原结束时刻之前不出现新增可见几何、结束后的延迟触发、原暂停控制、完整失稳与运动阶段、最终堆积和清除。检查中快进原时钟以验证衔接边界，并未重新求解或逐秒验证 RAMMS 数据。完整后阶段与清除后，原 TerrainData 引用及所有高度采样均保持一致。

默认创建 411 个岩土块与巨石，另有连续碎屑表层、张裂缝和沉积物雾。检查导出的图片使用临时中性照明并关闭浓雾，便于查看几何；这些检查设置不会写入运行场景。VR 场景采用同一后阶段入口与兼容立体渲染的材质，本次未佩戴 VR 设备检查交互。
